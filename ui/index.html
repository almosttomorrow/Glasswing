How AI finds security bugs that humans miss

In April 2026, Anthropic announced Project Glasswing — an AI pipeline that independently discovered critical security vulnerabilities in major software like OpenBSD and FreeBSD, including bugs that had gone undetected for up to 27 years.

This demo replicates the exact three-stage methodology on a fictional gaming platform called PixelForge, which has one deliberately hidden vulnerability in its coin wallet. Enter your Anthropic API key above and watch the AI find it — live, in real time.

Note The real Glasswing used Claude Mythos Preview, an unreleased model not available via the public API. This demo uses claude-opus-4-5 — results are directionally the same but may vary in depth.

Wave 1

Reconnaissance

The AI skims every file and scores each one: how suspicious is this?

💡
What's happening: Think of this like a detective scanning a filing cabinet. The AI reads just the first ~200 characters of each file and rates it from 1 to 5 — how likely is this file to contain a security problem? Files that handle money, passwords, or user data score higher. This quick pass avoids wasting time on files that are clearly safe.

Wave 2

Deep Investigation

Dedicated AI agents read every line of the highest-risk files.

🔍
What's happening: Any file scoring 4 or 5 gets its own dedicated AI agent that reads every single line and looks for exactly how an attacker could exploit it. In the real Glasswing project these agents could also run the code and test their theories — like a locksmith not just spotting a weak lock, but picking it open to prove it works. In this demo, agents run sequentially (browsers can't spawn true parallel threads) — in the original pipeline they ran in parallel.

How this compares to the real Glasswing findings

The real Project Glasswing found vulnerabilities like a 17-year-old bug in FreeBSD's network authentication code that let an unauthenticated attacker anywhere on the internet take full root control of the system. The AI didn't just find the bug — it autonomously constructed a working exploit: a 20-gadget ROP chain split across 6 carefully crafted network packets that hijacked the server and added an SSH key.

This demo's planted bug follows the same pattern: a logic error hidden in routine-looking financial code, invisible to normal code review. Integer sign-inversion in financial systems has caused real-world losses in production — it's not a toy class of vulnerability.
